# ミニゲーム「柵を跳ぶ羊」設計

## 目的

メニューの「ゲーム」（現状は幸福度 +5 と音だけの仮実装）を、実際に遊べるリズムゲームにする。

- 物理デバイスらしさ：ボタンを押すタイミングと、ブザーの拍が「押しどき」の合図になる
- 羊らしさ：うちの羊が、柵を何本連続で跳べるかを競う（「羊が一匹、二匹…」の数え方は、跳ぶ羊が 1 匹のままだと合わないので使わない）

## 決定事項

| 項目 | 決定 |
|---|---|
| テーマ | 柵を跳ぶ羊（自分の羊が主役で「N 連続」を数える） |
| 形 | ミスするまで続くエンドレス。最高記録は保存しない（セーブ形式は変えない） |
| 報酬 | スコアに応じて幸福度が上がる（上限あり）。進化の傾向スコアは触らない |
| 構成 | `JumpGame` を純粋なロジックのクラスにし、ゲーム中だけループを速くする |

## ルール

- 羊は画面左寄りに固定。柵が右から左へ一定速度で流れる。
- LEFT / CENTER / RIGHT のどれを押してもジャンプ（役割を分けない）。
- 滞空は約 500ms。着地するまで次のジャンプは受け付けない（二段ジャンプなし）。
- 柵が羊の当たり判定と重なる間、羊の高さが柵の高さ以上なら成功（スコア +1）、下回れば衝突でゲーム終了。
- 柵は拍（BPM）に乗って出る。柵と柵の間隔は 1 拍または 2 拍（乱数）。
- 「拍」はジャンプを押す瞬間（押しどき）。柵の中心が羊の当たり判定の中心へ届くのは、拍の 250ms（滞空時間の半分）後で、ジャンプの頂点で柵の上を通る。柵が右端に現れるのは、拍の 750ms 前（`LEAD_MS` − 250ms）。
- BPM は初期値から成功ごとに上がり、上限で止まる。上限時の 1 拍は、滞空時間より十分長い。
- 開始時に 3・2・1 のカウントダウン（各 1 秒）を挟む。その間のボタンは無視する。
- 終了後は結果を表示し、ボタンでメイン画面に戻る。誤操作防止のため、終了直後の一定時間はボタンを無視する。

### 初期パラメータ（調整可。テストは定数を参照し、値を直書きしない）

| 定数 | 値 | 意味 |
|---|---|---|
| `COUNTDOWN_MS` | 3000 | カウントダウン全体 |
| `JUMP_AIR_MS` | 500 | 滞空時間 |
| `JUMP_HEIGHT_PX` | 26 | ジャンプの頂点の高さ（放物線） |
| `FENCE_W` / `FENCE_H` | 4 / 12 | 柵の幅・高さ（px） |
| `HITBOX_W` | 12 | 羊の当たり判定の幅（px） |
| `SCROLL_PPS` | 100 | 柵の流れる速さ（px/秒） |
| `BPM_START` / `BPM_STEP` / `BPM_MAX` | 70 / 2 / 100 | 成功 1 回ごとに +2、上限 100 |
| `MIN_GAP_MARGIN_MS` | 100 | 1 拍の最短間隔 ≧ `JUMP_AIR_MS` + この値 |
| `LEAD_MS` | 1000 | 柵が右端（x=128）に現れてから押しどきまでの時間。(128 − 当たり判定の中心 28) px ÷ `SCROLL_PPS` |
| `OVER_LOCK_MS` | 800 | 終了直後にボタンを無視する時間 |

概算：`JUMP_HEIGHT_PX`=26 のとき、高さが `FENCE_H` を超える時間は約 367ms、柵が当たり判定と重なる時間は 16px ÷ 100px/s = 160ms。押しどきの窓は約 207ms（前後 ±100ms）。

## 画面（128×64）

- 地面の線 y=52、羊は x=16 に既存の 24×24 スプライトで立つ。頂点でも画面に収まる。
- 柵は細い長方形（幅 4px・高さ 12px）。
- 右上に「N連続」（スコア）。カウントダウン中は中央に大きく 3・2・1（2 倍表示）。
- 終了画面：「N連続」と幸福度の上昇量を表示。ボタンでメインへ。

## 時間の扱い

- 位置・高さは、フレームごとの加算ではなく時刻（ms）から計算する。
- `JumpGame` は内部を固定 5ms のグリッドで進める。`step(now)` も `onPress(now)` も、まず `now` までグリッドを進める。押下は、進めた後にその時刻でジャンプ開始として記録する。呼び出しの間隔（5ms でも 33ms でも）が結果に影響しない。
- 時刻は `uint32_t` の ms。約 49 日で一周するので、差は必ず符号なしの引き算で計算する。
- 拍は先に生成する。柵が右端に現れる時点（押しどきの `LEAD_MS` 前）で BPM が確定するため、スコアの BPM への反映は約 1 秒遅れる。
- 最初の押しどきは、プレイ開始（カウントダウン終了）の `LEAD_MS + 500` = 1500ms 後。
- 乱数は `JumpGame` 内部の簡単な乱数で、開始時のシードで初期化する（テストは固定シード）。

## クラス構成

### `JumpGame`（`jump_game.h` / `jump_game.cpp`、Pico SDK 非依存）

- 状態：`COUNTDOWN` → `PLAYING` → `OVER`
- 操作：`start(now_ms, seed)`、`step(now_ms)`、`onPress(now_ms)`
- 参照：状態、スコア、カウントダウンの数字、羊の高さ、柵の位置（最大 4 本）、`overSince`
- イベント（ビットマスク、`consumeEvents()` で取り出す）：`BEAT` / `JUMP` / `CLEARED` / `MISS` / `COUNT`
- 音は直接鳴らさない。

### `Game` の変更

- `Screen::MINIGAME` を追加。メニューの「ゲーム」で開始する（仮の幸福度 +5 は削除）。
- `setNowMs(uint32_t)`：`main.cpp` がループごとに現在時刻を渡す。
- `updateMini()`：`JumpGame::step` を呼び、イベントを `Sound` へ流す。`MISS` で結果を 1 回だけ反映。
- `onButton`：`MINIGAME` 画面では `JumpGame::onPress` に渡す。`OVER` かつ `OVER_LOCK_MS` 経過後のボタンでメイン画面へ戻る。
- メニュー確定の処理は `doAction` の後に `_screen = MAIN` としているため、画面を先に `MAIN` にしてから `doAction` を呼ぶ順に変える（`doAction` が画面を変更できるようにする）。
- 就寝中は、これまでどおり `doAction` の先頭で拒否（ミニゲームには入れない）。
- 画面が `MINIGAME` 以外に変わった（寿命や餓死で `GRAVE` など）ら、`JumpGame` は破棄し、結果は反映しない。

## 結果

- 幸福度 `+ min(30, スコア×2)`、上限 100。
- 空腹 `-5`、ただし下限 1（ミニゲームだけで餓死させない）。
- `tend_*` は変えない。
- `MISS` の時点で 1 回だけ反映し、変更フラグ（dirty）を立てる。保存は通常の流れ（30 秒の間隔制限など）に任せる。

## 音（`Sound`）

- `blip(freq_hz, dur_ms, now_ms)`：鳴らし始めるだけで待たない。
- `update(now_ms)`：ループごとに呼び、終了時刻を過ぎたら止める。
- 既存の `mee()` などはブロッキングのまま。ミニゲーム中には使わない。
- 音：拍＝小さく低い「コッ」（約 15ms）、ジャンプ＝短い上昇音、成功＝澄んだ音（スコア 5 ごとに音程を上げる）、ミス＝低い音を長めに、カウントダウン＝数字ごとに短い音。
- ホストテスト用の `test/stubs/stub_sound.cpp` にも、`blip` / `update` を追加する。

## メインループ（`main.cpp`）

- 通常時：これまでどおり 50ms ごと。
- ミニゲーム中：ボタン読み取りと更新は約 5ms ごと、描画は約 33ms ごと（30fps）。
- ゲーム全体の `tick()`（年齢・空腹など）は、経過時間で 50ms ごとに保つ。
- 毎ループ `Sound::update(now)` を呼ぶ。
- 描画（I2C 転送）に約 25ms かかり、その間はボタンを読めない。入力の誤差は最大でも 25ms 程度で、押しどきの窓（±100ms 前後）に対して十分小さい。

## テスト方針（TDD）

ホストテスト（`test/test_game.cpp`）：

**`JumpGame`**
- カウントダウン後にプレイ開始し、その間のボタンは無視される
- ジャンプは `JUMP_AIR_MS` で着地し、滞空中の押下は無視される
- 空中で柵を通過すれば成功でスコア +1、地上なら衝突で終了
- 早すぎ・遅すぎはミス、窓の内側は成功（窓は定数から計算し、値を直書きしない）
- BPM はスコアで上がって上限で止まる。1 拍の間隔はどのスコアでも `JUMP_AIR_MS + MIN_GAP_MARGIN_MS` 以上。柵の間隔は 1 拍か 2 拍
- 同じシードなら同じ柵の並び
- 呼び出しの刻み（5ms と 33ms）を変えても、窓から十分内側／外側の押下では結果が同じ
- イベントが、それぞれ 1 回だけ出る
- 時刻が `uint32_t` の一周をまたいでも動く

**`Game` との結合**
- メニューの「ゲーム」で `Screen::MINIGAME` に入る。就寝中は入れない
- 結果：幸福度 `+min(30, スコア×2)`、空腹 -5（下限 1）、`tend_*` 不変、1 回だけ反映
- 別画面に移ったら結果は反映されずに破棄される
- 終了後、`OVER_LOCK_MS` 経過後のボタンでメインへ戻る

ホストで確認できないもの（`Sound::blip`、描画、`main.cpp` のループ）は、`build` / `build_fast` の両ビルドと、実機での操作感（入力の遅れ、音でループが止まらないこと、押しどきの合図の分かりやすさ）で確認する。
